# HTTP: Версии протокола и Статус-коды

---

## 1. Эволюция версий HTTP

| Версия       | Базовый транспорт | Формат   | Конкурентность      | Главная фича / Проблема                                                                                                                  |
| :----------- | :---------------- | :------- | :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------- |
| **HTTP/1.0** | TCP               | Текст    | 1 запрос = 1 TCP    | Дорогой оверхед на TCP/TLS хэндшейки на каждый запрос.                                                                                   |
| **HTTP/1.1** | TCP               | Текст    | Очередь в 1 TCP     | **Keep-Alive** (соединение не рвется).<br>⚠️ *HoL Blocking (L7)*: запросы идут строго по очереди.                                        |
| **HTTP/2**   | TCP               | Бинарный | Мультиплексирование | Сотни параллельных стримов в **одном TCP**; сжатие заголовков (HPACK).<br>⚠️ *TCP HoL Blocking (L4)*: потеря пакета стопорит все потоки. |
| **HTTP/3**   | **QUIC (UDP)**    | Бинарный | Независимые стримы  | Нет HoL Blocking вообще; 0-RTT хэндшейк; соединение не рвется при смене сети (Wi-Fi $\to$ LTE).                                          |

> [!tip] Главное отличие для собеседования
> * **HTTP/1.1** открывает несколько TCP-коннектов (до 6 на домен), запросы внутри коннекта идут *последовательно*.
> * **HTTP/2** использует *одно* TCP-соединение, запросы идут *одновременно (вперемешку фреймами)*.
> * **HTTP/3** уходит с TCP на *UDP (QUIC)*, решая проблему заторов на уровне сети.

---

## 2. Группы статус-кодов

* **1xx (Informational):** Запрос получен, обработка продолжается.
* **2xx (Success):** Действие успешно получено, понято и обработано.
* **3xx (Redirection):** Клиенту нужно сделать доп. действие (перейти по новому адресу/взять из кэша).
* **4xx (Client Error):** Ошибка на стороне клиента (неверные данные, нет прав).
* **5xx (Server Error):** Ошибка на стороне сервера (упал, не справился, сбой шлюза).

---

## 3. Топ статус-кодов (Шпаргалка)

### 1xx — Информационные
* `101 Switching Protocols` — переход на другой протокол (например, апгрейд HTTP в **WebSocket**).

### 2xx — Успех
* `200 OK` — стандартный успешный ответ (`GET`, `PUT`).
* `201 Created` — ресурс успешно создан (`POST`). В заголовке `Location` отдается ссылка на него.
* `204 No Content` — запрос успешен, но тела ответа нет (`DELETE`, `PUT`).

### 3xx — Перенаправление и Кэш
* `301 Moved Permanently` — постоянный редирект (кэшируется браузером, SEO-вес передается).
* `302 Found` (Moved Temporarily) — временный редирект.
* `304 Not Modified` — ресурс не изменился (валидация кэша через заголовки `ETag` / `If-None-Match`), тело ответа не шлется.

### 4xx — Ошибки клиента
* `400 Bad Request` — синтаксическая ошибка (битый JSON, некорректный формат запроса).
* `401 Unauthorized` — **нет аутентификации** («Ты кто? Предъяви токен/логин»).
* `403 Forbidden` — **нет авторизации** («Я знаю кто ты, но у тебя нет прав на этот ресурс»).
* `404 Not Found` — ресурс не найден.
* `405 Method Not Allowed` — метод не поддерживается этим URI (например, `POST` на ручку, где есть только `GET`).
* `409 Conflict` — конфликт состояния ресурса (например, попытка создать пользователя с уже занятым email).
* `422 Unprocessable Entity` — синтаксис верен, но данные не прошли бизнес-валидацию (например, возраст отрицательный).
* `429 Too Many Requests` — сработал Rate Limiter (превышен лимит запросов).

### 5xx — Ошибки сервера
* `500 Internal Server Error` — паника/необработанное исключение в коде сервиса.
* `502 Bad Gateway` — Nginx/бэкэнд получил невалидный ответ (или разрыв соединения) от upstream-сервиса (сервис упал).
* `503 Service Unavailable` — сервер перегружен или выключен на обслуживание.
* `504 Gateway Timeout` — прокси/балансировщик не дождался ответа от upstream-сервиса за отведенный таймаут.
