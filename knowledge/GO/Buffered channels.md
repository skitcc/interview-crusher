# Буферизированные каналы

Канал с буфером работает как обычный канал, но:

- блокировка на запись — только при полностью заполненном буфере;
- блокировка на чтение — только при пустом буфере.

У небуферизированного канала ёмкость 0, каждая передача — рандеву. Буфер эту встречу откладывает, поэтому каналы с буфером и без буфера не взаимозаменяемы. Таблица состояний — в [[Channels]].

## Пример, где данные пропадают

```go
func main() {
	ch := make(chan int, 3)

	go func ()  {
		for range 3 {
			val := <- ch
			fmt.Println(val)
		}
	}()
	ch <- 1
	ch <- 2
	ch <- 3
}
```

Операции с каналом здесь определены, undefined behavior языка нет. Ломается время жизни процесса.

Буфер вмещает 3 элемента, поэтому три записи из `main` не блокируются. Читатель не куколдит, пока буфер заполнят: он читает параллельно с записью, а запись при свободном месте его не ждёт. `main` после трёх отправок заканчивается, процесс завершается, и `fmt.Println` может не успеть. То же самое, если получатель отвалился раньше: значения уже лежат в буфере, забирать их некому.

Для потока, который нельзя потерять, буфер канала — не очередь. В [[Channels]] тот же вывод: такой поток отдают наружу, например в Kafka.

## Единственный пример, который стоит помнить: `signal.Notify`

Буфер нужен, чтобы не блокировать доставку сигнала. Пакет `signal` отрабатывает в текущем процессе: `Notify` подписывает этот процесс на сигнал, а значение приходит в канал этой же программы.

```go
package main

import (
	"fmt"
	"os"
	"os/signal"
)


func main() {
	ch := make(chan os.Signal, 1)
	signal.Notify(ch, os.Interrupt)
	<- ch
	fmt.Println("shutdown")
}
```

`signal.Notify` не блокируется на отправке. Документация пакета прямо говорит: место в канале обеспечивает вызывающий, для одного значения сигнала достаточен буфер 1. Сигнал, пришедший раньше `<-ch`, остаётся в буфере. На небуферизированном канале в этот момент получателя нет, отправка не ждёт, и сигнал теряется.

> [!WARNING] Свой вывод
> Буферизованные каналы — кал как способ передавать данные. Буфер оправдан там, где он кодирует ограничение, а не ленту значений: `signal.Notify`, семафор, рейт-лимит. Передача «из рук в руки» — небуферизированный канал.
